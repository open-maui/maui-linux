# Changelog

All notable changes to this project will be documented in this file.

Version numbers are aligned with .NET / MAUI versions (e.g., OpenMaui 10.0.x targets .NET 10 / MAUI 10).

## [10.0.110.7] - unreleased

### Added

- **A gate on MAUI's handler mappings** (`MapperParityTests`): every property and command MAUI's own handler maps for a control must be mapped by OpenMaui's handler, or be listed as a known gap; the test fails when MAUI gains a mapping Linux does not handle, and when a listed gap gets mapped. It lists the 107 open gaps of 2,135 mappings across the 58 mapped controls (CollectionView grouping, header and footer templates; SearchBar's entry properties; shape stroke details; `TextTransform`; picker `IsOpen`, among them).
- **Geolocation listens**: `StartListeningForegroundAsync` keeps a desktop-portal Location session open and raises `LocationChanged` for each fix (which also becomes the last known location), honouring the request's accuracy and `MinimumTime`; `StopListeningForeground` closes it. It returned false and never raised the event. As MAUI does, starting while listening throws.
- **`Battery.EnergySaverStatus` follows the desktop's power profile** (power-profiles-daemon or tuned-ppd on the system bus): on in "power-saver", off in any other profile, and `EnergySaverStatusChanged` is raised when it switches. It was always Unknown; it still is without the daemon.
- **Layouts run MAUI's own layout managers**: Grid, StackLayout, VerticalStackLayout, HorizontalStackLayout, FlexLayout and AbsoluteLayout are measured and arranged by `GridLayoutManager`, the stack managers, `FlexLayoutManager` and `AbsoluteLayoutManager`, as on every other platform, instead of OpenMaui's re-implementations, which had drifted from MAUI (span resolution, star rows, StackLayout `Orientation`, Fill with an explicit size). Spans, star and Auto sizing, spacing, alignment, collapsed children and attached-property changes now behave exactly as in MAUI, and right-to-left layouts mirror their children as Android and iOS do. FlexLayout item margins apply as MAUI applies them (the flex engine spaces items by their margins and each item is inset by its margin again, so a margin counts twice). `SkiaGrid`, `SkiaStackLayout`, `SkiaFlexLayout` and `SkiaAbsoluteLayout` remain for views composed directly in Skia.
- **A Windows-vs-Linux layout comparison** (`tools/ParityHarness`): a gallery app dumps every element's frame on WinUI and on Linux at the same window size, and a diff tool reports the elements placed differently (with a separate tolerance for text, whose metrics differ by platform). The manual `parity` workflow runs both and publishes the report.
- **dotnet/maui's own handler tests run against the Linux handlers** (`tests/Conformance`): 1,475 of MAUI 10.0.110's handler conformance tests for 22 controls, compiled from a sparse checkout of dotnet/maui (`tests/Conformance/get-maui-sources.sh`) with Linux versions of their platform helpers, so MAUI's assertions are the specification. 795 pass; the 574 failures are parity gaps, grouped and diagnosed in `docs/CONFORMANCE.md` (chief among them: base view properties such as Opacity, Visibility, FlowDirection and semantics are applied only when a page creates the handler, not through the handler's mapper). The suite is separate from the main tests so its open gaps do not fail the build.
- **The input method learns each field's content type**: `Keyboard` (numeric, telephone, email, URL, date, time, chat, text, custom flags), password fields and the prediction and spell-check settings become the input method's purpose and hints (text-input-v3 `set_content_type` on Wayland, `SetContentType` on IBus 1.5.4+), updated live while the field has focus. New: `TextInputContentType`, `TextInputPurpose`, `TextInputHints`, and default-implemented `IInputContext.ContentType` and `IInputMethodService.NotifyContentTypeChanged()`.
- **Images load through MAUI's image-source services**, as on the other platforms: `ILinuxImageSourceService.GetImageAsync(IImageSource, float scale, CancellationToken)` is the Linux counterpart of Android's `GetDrawableAsync`, iOS's `GetImageAsync` and Windows' `GetImageSourceAsync`, returning a `LinuxImageSourceServiceResult`. `UseLinux` registers `LinuxFileImageSourceService`, `LinuxUriImageSourceService`, `LinuxStreamImageSourceService` and `LinuxFontImageSourceService` through `ConfigureImageSources`; Image and ImageButton resolve the service for the source's type, so an app or library can add its own `IImageSource` with `services.AddService<TSource, TService>()`, which could not load before. A load replaced by a newer one is cancelled and never shown; SVG and font images render at the window's scale (sharp on HiDPI); ImageButton shares the image cache and embedded-resource lookup with Image; a picture that cannot be decoded fails its load (it reported success with no picture); Uri images honour `CachingEnabled`. Button images, Shell toolbar and flyout icons, NavigationPage toolbar icons and ImageCell images in ListView and TableView load through the same services (any source kind, including font images and an app's own, at the size they are drawn and the screen's density; a replaced picture is released, where ImageCell's never was): button images supported only files, streams and URIs, and the icons and ImageCell only files (ImageCell without the SVG fallback or the app's resource folders).
- **Page checks for any app** (`OPENMAUI_INVARIANTS=1`): each page is checked a second after it appears, and every five seconds while it stays, against rules every MAUI page should satisfy, and what is broken is printed to stderr: text that is a type name (an object drawn through ToString), an image or video drawing outside its frame, a visible enabled control a click at its centre does not reach, text cut off by its own height or by a view around it too short for it (truncating on purpose is allowed), failed bindings (MAUI's binding diagnostics are switched on for it), and errors logged while the page was shown. The rules catch whole classes of parity bugs on any page without a test written for it; run on CiteLynq they found the row binding order fixed below, and two of the app's own broken bindings.
- **Tests and parity gates run in CI, in their own workflow**: `.gitea/workflows/tests.yml` runs the main suite (golden screenshots against the committed baselines), the mapper parity gate, the third-party compat suite, every MAUI conformance suite (dotnet/maui's sources fetched and cached) and the stub scan, each as its own step; a failure turns the run red and every result file is published. It only reports: builds and releases do not wait for it. The `dotnet test` steps in ci.yml and release.yml ran no tests (the repository root has no test project) and are removed.
- **Third-party stub scan** (`tools/StubScan`): compares the platform-neutral and Windows builds of Syncfusion, CommunityToolkit and MAUI's own assemblies, and fails when a library update brings in a stub nobody has reviewed. `tools/StubScan/baseline.json` records each of the 2,313 current findings as covered (naming the OpenMaui file that bridges it), not applicable, or open. The first scan found 561 open gaps; this release closes all but 91, which are listed in `docs/STUBS.md` (75 of them are the Syncfusion Scheduler's desktop resource view).
- **dotnet/maui's Controls device tests run against OpenMaui** (`tests/Conformance/Controls`): 604 of MAUI 10.0.110's Controls-level tests (real Label, Entry, CollectionView, Shell, NavigationPage, TabbedPage, FlyoutPage, modal pages, windows, memory-leak checks...) hosted in a headless window on OpenMaui's own main thread, the layer real apps use. The first run failed 257; fixes in this release bring that to 0 (600 passed, 4 skipped for mechanisms Linux does not have; `docs/CONFORMANCE.md`). `-p:MauiSrc=` now works without a trailing slash (it silently reduced either conformance suite to one skipped test).
- **`ShapeViewHandler` and `RoundRectangleHandler`**: any `IShapeView` (a library's own shape included) now gets a Linux handler with MAUI's full shape mapper, and `RoundRectangle` is supported. Shapes and BoxView draw MAUI's own `ShapeDrawable`, so gradient fills, line caps and joins, miter limit, `Aspect`, a Path's `RenderTransform` and Polygon/Polyline `FillRule` render as on the other platforms. The existing shape handlers keep their types and now chain this mapper.
- **Shell shows its bottom tab bar**: the current item's sections (the tabs of a TabBar or FlyoutItem) appear as bottom tabs when the item has more than one section and `Shell.TabBarIsVisible` allows it, each with its icon and title in the Shell's `TabBarForegroundColor`, `TabBarTitleColor`, `TabBarUnselectedColor`, `TabBarDisabledColor` and `TabBarBackgroundColor`; a click selects the section. Before, a Shell app had no tab bar at all.
- **`Shell.TitleView`** is drawn in the navigation bar (the page's, else the nearest one set above it) and follows page and property changes.
- **`Window.Toolbar` has a Linux `ToolbarHandler`**; the window keeps the platform toolbar as `SkiaWindow.Toolbar`. `Shell.FlyoutHeaderBehavior` reaches the platform (a CollapseOnScroll header is at least 56 tall) and `SkiaShell.FlyoutBounds` exposes the flyout panel.
- **`CoreSwipeViewHandler` and `SwipeItemViewHandler`**: any `ISwipeView` (a library's own swipe view, not only Controls' SwipeView) and any `ISwipeItemView` get a Linux handler with MAUI's mapper and command mapper (`RequestOpen`, `RequestClose`); `SwipeItemMenuItemHandler` serves any `ISwipeItemMenuItem`. MAUI's Core SwipeView handler tests now run against them.
- **Handlers for MAUI's core interfaces**: a library's own `IRefreshView`, `IIndicatorView`, page (`IContentView`) or `IStackNavigationView` gets a working Linux handler (`CoreRefreshViewHandler`, `CoreIndicatorViewHandler`, `CorePageHandler`, `CoreNavigationViewHandler`) instead of MAUI's platform-neutral one, which has no platform view. MAUI's Core RefreshView, IndicatorView, View, Element, Window, Page and Navigation handler tests now run against OpenMaui (Core conformance: 0 failed).
- **`VisualElement.CaptureAsync()` and `Window.CaptureAsync()` return an image** of the view or window (they returned null).
- **`Window.DisplayDensity`** reports the scale of the monitor the window is on (it was always 1).
- **dotnet/maui's Essentials device tests run against OpenMaui** (`tests/Conformance/Essentials`, its own step in the tests workflow): 281 ported, 0 failing on a desktop session; tests that need a person, hardware the machine lacks, a missing desktop application or network access are skipped with the reason. The first run failed 54.
- **Geocoding works on Linux, opt-in**: set `GeocodingService.ServiceUrl` (or `OPENMAUI_GEOCODING_URL`) to a Nominatim service (self-hosted, commercial, or `GeocodingService.OpenStreetMapUrl` for light use under its policy) and `Geocoding` returns real placemarks and locations; without one it throws `FeatureNotSupportedException` and no address or position leaves the machine, as Windows needs the app's map key. It returned nothing before.
- **HybridWebView works on Linux** (WPE WebKit, or WebKitGTK in GTK mode), as on iOS and Mac Catalyst, which also run WebKit: the web app is served from `app://0.0.0.1/` out of `Resources/Raw/{HybridRoot}` (`DefaultFile` for the root) with MAUI's own `hybridwebview.js`; `SendRawMessage`/`RawMessageReceived`, `InvokeJavaScriptAsync`, `window.HybridWebView.InvokeDotNet`, `EvaluateJavaScriptAsync`, `WebViewInitializing`/`WebViewInitialized` and `AddHybridWebViewDeveloperTools()` behave as there. `WebResourceRequested` is raised for app-origin requests with MAUI's own event arguments (`SetResponse` with a stream or a `Task<Stream>`); as on iOS, WebKit cannot intercept http and https requests. It had no Linux handler before.
- **`WebKitContentApi`**: per-view custom URI scheme handlers with the request's method, headers and body and asynchronous responses with headers (`RegisterUriSchemeHandler`, `SchemeRequest`), removable script-message handlers (`AddScriptMessageHandler`) and `SetDeveloperExtrasEnabled`. `RegisterUriScheme` now serves the views that have no handler of their own, so BlazorWebView and HybridWebView share the `app` scheme.
- **CollectionView `CanReorderItems`**: drag an item to a new place with the mouse, as on Windows (Escape cancels); the source is updated and `ReorderCompleted` is raised. Grouped lists move items within a group, or across groups with `CanMixGroups`, as on iOS and Android.
- **CarouselView**: `EmptyView`/`EmptyViewTemplate`, scroll-bar visibility, `Loop`, and a vertical `ItemsLayout` with `ItemSpacing`.
- **Motion and environment sensors** (Accelerometer, Gyroscope, Magnetometer, Compass, Barometer, OrientationSensor) work on machines with sensor hardware (convertibles, tablets, phones): they read the kernel's IIO devices and report MAUI's units at MAUI's intervals. `IsSupported` is true only where the hardware is; without it `Start` and `Stop` throw `FeatureNotSupportedException`, as on Windows.
- **`MediaPicker.CapturePhotoAsync` and `CaptureVideoAsync`** open a camera dialog over the app window (take, retake or use a photo; record and stop a video), reading the camera through GStreamer, directly or through the desktop's camera portal in a sandbox. Photos are JPEG; videos are MP4 (H.264 and AAC), or WebM without those encoders. `IsCaptureSupported` reports whether a camera is there.
- **Contacts** are read from Evolution Data Server (GNOME Contacts, Evolution, GNOME Online Accounts): `GetAllAsync` and `PickContactAsync` work; without it they throw `FeatureNotSupportedException`, and `PermissionException` when a sandbox denies access. KDE's Akonadi is not supported.
- **CommunityToolkit TouchBehavior and ImageTouchBehavior** work: pressed and hover states (colours, scale, opacity, translation, rotation, images), `Command` and `LongPressCommand`, as on Windows.
- **CommunityToolkit Toast and Snackbar** show as desktop notifications, as the toolkit does on Windows: the Snackbar's action button runs its `Action`, the alert goes after its duration, and `Shown` and `Dismissed` are raised.
- **CommunityToolkit `Badge.SetCount`** sets the app's launcher badge (the Unity LauncherEntry API: KDE Plasma, Dash to Dock, Plank and others) instead of throwing.
- **CommunityToolkit DrawingView**: `GetImageStream` returns the drawing as a PNG, a custom `IDrawingLineAdapter` is used, and drawn lines are smoothed as on the toolkit's other platforms. `SemanticOrderView` sets the screen reader's reading order.
- **NavigationPage bar**: `NavigationPage.TitleView` (in the title's place, taking its own input), `TitleIconImageSource` (before the title), `IconColor` (the back arrow) and a gradient `BarBackground` are shown, laid out as on Windows; `BackButtonTitle` is carried as on Windows, which shows no back-button text.
- **Window overlays**: `Window.AddOverlay` and the visual diagnostics overlay (adorners) draw over the page; `WindowOverlay.Tapped` is raised, and `EnableDrawableTouchHandling`/`DisableUITouchEventPassthrough` keep taps from the page, as on Windows.
- **`Window.TitleBar`** (MAUI 9+): the custom title bar is shown above the page. With client-side decorations it fills the window's title bar (its content takes clicks, the rest moves the window); otherwise it is a strip at the top of the window.
- **Pickers `IsOpen`**: Picker, DatePicker and TimePicker open and close from code, and `IsOpen` follows the user (Opened and Closed are raised). `Slider.ThumbImageSource` draws the image as the thumb; `Stepper.Interval` and `Picker.Items` are mapped.
- **Tab and Shift+Tab move keyboard focus** between the page's focusable views (in tree order, wrapping), as on the other desktop platforms; a view that uses Tab itself (an Editor) keeps it. There was no Tab navigation before.
- **Syncfusion SfNumericEntry**: Up/Down and PageUp/PageDown step the value, the mouse wheel steps a focused entry, only number characters are accepted, and paste, cut, Backspace, Delete, Enter, Escape and Ctrl+Z/Y behave as on Windows. **SfMaskedEntry**: typing, Backspace, Delete, paste and cut go through the mask; focus puts the caret on the first prompt (or selects all with `SelectAllOnFocus`).
- **Syncfusion SfComboBox and SfAutocomplete**: Backspace and Delete remove multi-selection chips, the chip area follows the control's width, the drop-down matches the control's width and closes on page navigation, on Tab and (inside a template) on focus loss, and `SelectionTextHighlightColor` is applied. SfNumericEntry, SfMaskedEntry, SfComboBox, SfAutocomplete and SfTextInputLayout show hover states and follow the control's `FlowDirection`.
- **Syncfusion, smaller**: SfPicker columns can be dragged with the mouse, and pans report a release velocity (inertia); SfCarousel honours `EnableVirtualization`; SfCalendar lays out again when `FlowDirection` changes; Shift+wheel scrolls SfInteractiveScrollView horizontally; Syncfusion buttons and SfSegmentedControl are Tab stops; the drawn parts of Syncfusion views are exposed to screen readers.
- **MediaElement behaves as on Windows**: `MediaOpened`, `MediaFailed`, `SeekCompleted` and `StateChanged` are raised, and `CurrentState` moves through Opening, Buffering, Playing, Paused, Stopped and None. Setting `Source` opens the media straight away, so `MediaOpened`, `Duration`, `MediaWidth` and `MediaHeight` arrive before `Play`. `Speed` sets the playback rate and keeps the audio's pitch (0 pauses). `UriMediaSource.HttpHeaders` are sent with the request for the media (or an HLS or DASH manifest, not its segments). `ShouldKeepScreenOn` keeps the screen saver off while playing.
- **MediaElement `ShouldShowPlaybackControls`** shows a playback controls bar: a seek bar with times, mute, play/pause, playback rate, repeat and zoom.
- **MediaElement metadata over MPRIS**: `MetadataTitle`, `MetadataArtist` and `MetadataArtworkUrl` are published, and the desktop's media widget and media keys control the player. An element without metadata (a background video) is never published; `OPENMAUI_MPRIS=0` turns publishing off.
- **Syncfusion SfDataGrid works with a mouse and keyboard, as on Windows**: scroll-state events, arrow-key, Page, Home and End navigation, undo and redo, right-click (`CellRightTapped` and the context menu), column and row resizing and dragging with resize and move cursors, header hover highlight, tool-tip delay, the current-row border, the column chooser on load, and images in Excel and PDF exports.
- **Syncfusion SfImageEditor edits images**: rotate, flip, crop (rectangle, circle, ellipse), the eight effects, undo and redo, `GetImageStream`, `Save` (through the desktop's Save dialog) and Browse; `View.GetStreamAsync` and `View.SaveAsImage` (chart export) render the view. It had no Linux view before.
- **Syncfusion SfScheduler with a mouse**: holding the button 300 ms raises `LongPressed` and drags an appointment; appointment edges resize with a resize cursor in the day, week, month, all-day and timeline views (the timeline header shows the new time); appointment tool tips on hover; header right-click. SfPullToRefresh pulls with a mouse drag.
- **Resize and move cursors** (`CursorType.SizeWestEast`, `SizeNorthSouth`, `SizeAll`) on X11 and Wayland; a cursor a view changes while the pointer is over it, or sets on a container, now shows.

### Fixed

- **`AppInfo.RequestedLayoutDirection` was always left-to-right**: it now follows the UI language (right-to-left for Arabic, Hebrew and the rest), as on the other platforms.
- **`Email.IsComposeSupported`, `Sms.IsComposeSupported` and `PhoneDialer.IsSupported` were always true**: they now report whether an application handles mailto:, sms: and tel: links (the XDG associations xdg-open uses; always true in a sandbox, where the portal chooses), and composing or dialling without one throws `FeatureNotSupportedException`, as MAUI does, instead of doing nothing. `Sms.ComposeAsync(null)` opens an empty message, as on the other platforms, instead of nothing.
- **Changing `CheckBox.Color` after the box was shown did not recolour it**: MAUI maps `Color` to a refresh of the check's colour, and the Linux handler had no such mapping (found by the mapping gate).
- **A ScrollView measured with unbounded room took a made-up 400 px**: in a VerticalStackLayout (which measures its children with unbounded height) it was 400 tall whatever its content, and a centred one took the full width. As in MAUI, a ScrollView is now as large as its content, up to the room offered: in a stack it is as tall as its content and does not scroll (use a Grid with a `*` row for a scrolling region, as MAUI's guidance says), and a centred one wraps its content.
- **MediaElement measured 0 x 0 in a MAUI layout**: its handler derives from the toolkit's portable handler, which a layout manager cannot measure; it is now measured and placed like the other controls.
- **A library control with its own `MeasureOverride` was measured twice per layout pass.**
- **Opacity, Visibility, FlowDirection, AutomationId, semantics, InputTransparent and ZIndex reach the platform view through the handler**, as on every other platform: they are mapped in MAUI's `ViewHandler.ViewMapper`, which every Linux handler inherits, from the core `IView`. They were copied from a Controls view only when OpenMaui created its handler, so `handler.UpdateValue` did nothing for them and a view that is not a Controls view (a library's core view) got none of them (330 of MAUI's conformance tests failed on this). `Visibility.Hidden` now keeps the view's layout space and draws nothing (it was treated as Collapsed); `SkiaView.Visibility` exposes it. An ActivityIndicator spins only while it is running and visible, and a layout reorders a child whose ZIndex changed (`UpdateZIndex`).
- **A Button whose handler is the plain `ButtonHandler` showed no text**: only the handler registered for Controls' Button mapped text, text colour, font and character spacing; any `ITextButton` (a library's core button) now gets them, and `Button.TextTransform` is applied.
- **RadioButton used only the font size**: its font family, bold and italic, character spacing, content of any `IRadioButton`, and border (stroke colour, thickness, corner radius) now reach the Linux view.
- **Picker, DatePicker and TimePicker ignored italic**, and their bold and italic applied only with a font family set: both now apply, and a typeface is no longer created (and leaked) on every frame.
- **Image and ImageButton raised none of MAUI's image loading notifications** (`IsLoading`, loading started, completed and failed), and a null source, or one that failed to load, kept the previous picture: they now report as on the other platforms and clear the picture. `IsAnimationPlaying` is mapped (an animated GIF starts and stops with it, and an animation no longer keeps running after a static image replaces it); ImageButton shows `FontImageSource` glyphs; a source the handler cannot load reports a failure instead of nothing.
- **Disconnecting a layout handler left its platform children attached**: they are detached, as MAUI's layout handlers do, so a recreated page can show them again.
- `ScrollViewHandler` has the `(IPropertyMapper?, CommandMapper?)` constructor the other handlers have.
- **Entry, Editor and SearchBar ignored `Keyboard`**: it is mapped on all three (Editor's mapping was empty; Entry and SearchBar had none).
- **`MaxLength` only limited typing**: as in MAUI, text set from code, and the current text when MaxLength is lowered, is cut to it; `0` allows no text and `-1` is unlimited (SkiaEntry's default is now -1); SearchBar maps MaxLength.
- **An app's null `Text` was overwritten with ""**, raising an extra TextChanged: the handlers write text back only when it really differs, treating null and "" alike as MAUI does; Editor reports "" rather than null, and a text cut by MaxLength or TextTransform is reported back to the view.
- **SearchBar lacked most text-input properties**: CursorPosition and SelectionLength (reported back after typing), IsReadOnly (its clear button and Escape no longer clear a read-only bar), IsTextPredictionEnabled, IsSpellCheckEnabled, VerticalTextAlignment, ReturnType, SearchIconColor, TextTransform and italic fonts now apply, and focusing it connects the input method to its field.
- **Focus did not reach `IsFocused`** for a view that is not a Controls element: Entry, Editor and SearchBar report their platform focus to it, as MAUI's handlers do. Entry and Editor map `TextTransform`, and Entry's `ReturnType` reaches the field.
- **A CollectionView's Header and Footer were drawn as text in fixed bands**: a View header showed its type name ("Microsoft.Maui.Controls.VerticalStackLayout", CiteLynq's library list), and `HeaderTemplate` and `FooterTemplate` were ignored. They are now views, as on every MAUI platform: a View as it is, a template's content bound to the header or footer object, or a label for a string. They are as tall as their content, scroll with the items, inherit the list's BindingContext and take input (a button in a header works; a tap there selects no item). An empty list shows them above and below its empty view.
- **Every CollectionView row (and CarouselView page, and Shell flyout row) first bound to the page's view model**: the row was attached to the list before it was given its item, so for a moment it inherited the list's BindingContext; compiled bindings (`x:DataType`) then failed once per row ("Mismatch between the specified x:DataType and the current binding context") and every binding ran twice. The item is now set first, as MAUI does.
- **NavigationPage**: pages inside it had no frame (Width and Height stayed -1, SizeChanged never fired), as it drew them without arranging them; they are arranged now. `PushAsync` and `PopAsync` complete after the transition, and a navigation during a transition is no longer dropped; pages inserted or removed beneath the current one, and stack swaps, are shown; `HasNavigationBar` and `HasBackButton` are honoured; the back arrow and Escape pop MAUI's navigation stack (the two stacks disagreed); a TabbedPage or FlyoutPage can be pushed; popped pages are released.
- **TabbedPage and FlyoutPage** give their pages a frame; FlyoutPage supports right-to-left.
- **Shell**: the Shell a window shows has a ShellHandler (it was rendered without one); a ShellContent page without Content is shown; `Shell.BackButtonBehavior` (`IsVisible`, `Command`) is honoured.
- **Windows**: `WindowHandler` implements `IWindowHandler`; modal pages pushed before the window opened are presented; closing a window raises Unloaded for its views, so platform behaviors detach.
- **Label**: `TextTransform` and `TextType` are applied, a span with the default transform uses the label's, and `MaxLines` follows MAUI's rules for truncating line-break modes. Button maps `LineBreakMode`; Editor maps `AutoSize`.
- **Entry and Editor**: `CursorPosition` and `SelectionLength` are capped to the text and reported back to the view, and text replaced after the field is shown moves the caret to the end.
- **A view's desired size could exceed the space it was offered** (a single-line label 100 pixels wide asked for 3,800): it is capped to the offer unless the view has an explicit size, as on the other platforms.
- **Smaller**: a CheckBox's `Background` paints the view's background, not the box; Picker keeps its `SelectedIndex` when its items are refilled; DatePicker shows no date when `Date` is null; Frame draws its `BorderColor` border and counts it in its size; ScrollView places content smaller than itself by the content's alignment.
- **Polygon and Polyline did not redraw when a point was added to `Points`**, and Border ignored `StrokeShape` and `StrokeDashPattern` changes through its mapper; the shape handlers now map every key MAUI's do.
- **`VisualTreeElementExtensions` found nothing on Linux**: `GetVisualTreeElements(point)` now tests each view's position in the window, and the element for a platform view is found as MAUI finds it.
- **Label**: with `TextType=Html` its `FormattedText` spans are ignored, as on the other platforms; centred and end-aligned text is placed by its advance width (it used the ink bounds, pushing right-aligned text past the edge by a pixel or two).
- **`AutomationProperties.ExcludedWithChildren` was ignored**: the view and its subtree now leave the accessible tree (`SkiaView.IsExcludedWithChildren`).
- **`Window.Width`, `Height` and `SizeChanged` never worked in a single-window app**: the startup window never reported its size to MAUI (only secondary windows did). Every window now reports its size when it opens and on every resize.
- **Shell**: a page no longer gets Appearing twice (after a push from `NavigatedTo`, or with a modal pushed before the window loaded); a popped page is no longer kept alive by the toolbar; flyout `ItemTemplate` rows are logical children of the section or content they show.
- **TabbedPage** draws its tab icons (tinted with the selected or unselected colour), follows its pages' `Title` and `IconImageSource` as they change, and paints `BarBackground` (gradients included); a shared gradient brush is released when the page leaves the screen.
- **A page with a CollectionView was never released after it closed**: the items source held the list, its handler and every item view. The source is now observed weakly and the handler releases its item views on disconnect. Realized items, the header and the footer are logical children of the CollectionView, as in MAUI.
- **`CollectionView.ScrollTo` did nothing** (MAUI raises an event OpenMaui did not listen to): scrolling by index, item or group now works, with `ScrollToPosition`. `CarouselView.ScrollTo` works too.
- **`CollectionView.IsGrouped` was ignored** (one row per group): groups show `GroupHeaderTemplate` and `GroupFooterTemplate` rows around their items, and follow collection changes.
- **A horizontal CollectionView was drawn as a vertical list**: a horizontal `LinearItemsLayout` lays its items in a row, sizes to them and scrolls sideways. An item's margin is inside its row.
- **CarouselView did not show items added after it appeared**; it now follows its collection and stops when disconnected.
- **A SwipeView row was cut to 44 px** (CiteLynq's Notifications rows lost their second line): a SwipeView is as tall as its content. Tapping a swipe item runs its `Command` and `Invoked` event, `SwipeItem` gets a Linux handler and honours `IsVisible`, and the default `Threshold` reveals the items.
- **ScrollView content lost its alignment on the next frame** after `HorizontalOptions` or `VerticalOptions` changed.
- **A handler connected through MAUI's own API** (`view.Handler = new XHandler()`) is now tied to its view as OpenMaui's handler factory ties it (frame, Loaded, layout options).
- **SwipeView behaves as on the other platforms**: `SwipeStarted`, `SwipeChanging` and `SwipeEnded` fire and `IsOpen` follows the swipe and `Open`/`Close`; a swipe can start on the content (a label or button in the row, CollectionView rows included) without clicking what is under the finger; the content slides with the finger; a side opens to its items' size and `Threshold` is the distance that opens it, as in MAUI; top and bottom items, `SwipeTransitionMode.Drag`, Execute mode and `SwipeBehaviorOnInvoked` work; a disabled item is not invoked and a hidden one takes no room; tapping an open SwipeView's content closes it. A `SwipeItemView` shows its content (it was a grey "Action" placeholder). `SkiaSwipeView.LeftSwipeThreshold` and `RightSwipeThreshold` now default to 0 (the open distance comes from the items; it was a fixed 100 px).
- **A window without a native display (embedded, or under test) ignored `Window.Width`, `Height`, `X` and `Y`** and its minimum and maximum sizes, and `Application.OpenWindow`/`CloseWindow` tried to create a native window; such a window now takes the geometry MAUI asks for.
- **Wrapped label text took the whole width offered**: it is now as wide as its widest line, as on Windows and iOS, so a Start, Center or End aligned label (and a frame around it) ends where its text does.

### Added

- **Runtime scale change.** A window moved to a monitor with a different scale, or a desktop scale change, now re-renders at the new density instead of keeping the startup scale. On Wayland the compositor's `wp_fractional_scale_v1.preferred_scale` resizes the buffer to logical size x new scale and the `wp_viewporter` destination keeps the window's logical size (the viewport is now created at every scale, including 1x); on X11 the window watches `RESOURCE_MANAGER` on the root window (Xft.dpi, rewritten by the desktop's settings daemon) and re-lays out at the new logical size. Each window has its own scale (`IScaleAwareDisplayWindow`); the rendering engine, pointer and scroll coordinates, and popups (pickers, date/time pickers, maps) use their own window's scale instead of the primary window's. `LinuxApplication.DpiScale` follows the primary window and raises `DpiScaleChanged`.
- **Live MAUI Window properties.** Replacing `Window.Page` (the post-login `Window.Page = new AppShell()` or `Application.MainPage =` swap) renders the new page into the window; before, the window kept showing the old page. `Window.Title`, `Width`/`Height`, `X`/`Y` (X11 only: Wayland clients cannot place windows) and `MinimumWidth`/`MinimumHeight`/`MaximumWidth`/`MaximumHeight` are applied to the native window, in logical pixels (`IDesktopWindowControl`: X11 `XResizeWindow`/`XMoveWindow`/`WM_NORMAL_HINTS`; Wayland surface resize and `xdg_toplevel.set_min_size`/`set_max_size`). Limits and position set before the window opens are applied when it is shown.
- **`IWindow.Stopped` / `Resumed`.** Minimizing or fully hiding a window raises `Window.Stopped` (and `Application.OnSleep`), restoring raises `Resumed` (`Application.OnResume`), for every window including the primary. Wayland reports it through the xdg-shell v6 `suspended` state (xdg-shell is now bound up to v6, with the v4 `configure_bounds` and v5 `wm_capabilities` events declared and ignored); X11 through the unmap that iconifying performs.
- **`openmaui doctor`** (`Diagnostics/OpenMauiDoctor.cs`). `OPENMAUI_DOCTOR=1 ./MyApp` (or `--openmaui-doctor`) prints a report and exits before any window is created: .NET and SkiaSharp versions, session and desktop, the display server the platform will use, the compositor and every Wayland global it advertises (fractional scale, viewporter, text-input-v3, dmabuf, decorations, data device, primary selection), EGL and GL renderer and the render target `RenderTargetFactory` will pick, the startup scale and which source detected it, the IME backend, and every optional native dependency (GTK 3, GStreamer, CUPS, AT-SPI2, AppIndicator, WebKitGTK, WPE WebKit, fontconfig, CJK and emoji fallback fonts) with the exact install command for the detected distribution. It reuses the platform's own probes, so it reports what will actually be selected. Exit code 1 when something required is missing. `OpenMauiDoctor.Run()`/`Format()` are public for apps that want to show it themselves.

- **Zero-copy WebView frames on the GPU target** (`Rendering/DmaBufFrameImporter.cs`, `Interop/Egl.DmaBuf.cs`). When the WebView is drawn by the EGL render target, each WPE DMA-BUF is imported as an EGLImage on the platform's own EGL display, bound to a GL texture and drawn by Skia as a borrowed texture: no pixel copy, no texture upload. Measured at 1280x800 on Mesa Intel: import 0.076 ms per frame against 3.8-3.9 ms for the copy path, draw and flush 1.25-1.48 ms against 2.5 ms. Used only when `EGL_EXT_image_dma_buf_import` (plus `_modifiers` for tiled buffers) and `GL_OES_EGL_image` are present and the EGL display is on the same GPU as WPE's render node (checked through `EGL_EXT_device_query` and sysfs, which matters on hybrid Intel/NVIDIA laptops); otherwise, on the raster target, or with `OPENMAUI_WEBVIEW_ZEROCOPY=0`, frames take the existing copy path. The path in use is logged once. WebKit's rendering fence becomes a GPU-side `eglWaitSync`; a released buffer carries an `EGL_ANDROID_native_fence_sync` release fence (`glFinish` without the extension). Details in `docs/WPE-EMBEDDING.md`.
- **Hardware keycodes in WebView key events.** `KeyEventArgs.HardwareKeycode` (XKB numbering; evdev + 8 on Wayland, the X keycode on X11, GDK's in GTK mode) reaches WPE, so pages see `KeyboardEvent.code` (`KeyA`, `ArrowLeft`, ...) as in any browser; printable keys, which reach WebKit as text input, are matched to the key press that produced them.
- **WebView follows the window's scale.** A window moved to a monitor of another scale re-renders its page at the new density (`devicePixelRatio` follows) while the CSS size is kept.
- **WebView conformance scenarios** `keyboard-event-code`, `frames-delivered-gpu` (headless EGL context on the matching device, asserts the zero-copy path and colours) and `scale-change` in `tests/WebViewHost`.

- **Partial damage on the GPU target.** Frames repaint and submit only what changed. Each view records the physical pixels it painted (after DPI scale, CSD inset, scroll offsets, its own transform, shadow and a small overflow margin); an invalidation damages where it was and where it will paint now, instead of bubbling the root's full bounds up the tree (which made every frame whole, on every target, and at HiDPI clipped raster repaints to logical coordinates). The EGL target reports `EGL_EXT_buffer_age`, so the engine repaints this frame's damage plus the damage of the frames that buffer missed, and submits with `eglSwapBuffersWithDamage` so the compositor recomposes only the damage. Frames stay whole when the buffer age is unknown, the history is too short, the damage covers most of the surface, or a popup, dialog or context menu is up (and on the frame it closes). `OPENMAUI_PARTIAL_DAMAGE=0` restores whole GPU frames.
- **Drag-and-drop onto secondary windows.** The backend now reports which window a drag is over (`DragDropService.CurrentTargetWindow`): Wayland per-window data devices pass their window, and on X11 every window announces XdndAware (`DragDropService.RegisterWindow`) with its XDND messages routed by window while selection transfers keep using the primary connection. Drops resolve in that window's tree, with that window's scale and CSD inset.
- **Secondary windows in GTK mode.** `Application.OpenWindow` works with `UseGtk = true`: the primary stays the GTK host window and secondaries are native OpenMaui windows pumped from GTK's main loop by a GLib timeout (events, Wayland reads, animations, render, reaping), removed again when the last secondary closes.
- **linux-arm64 Wayland shim.** `libopenmaui_wl.so` is now built for aarch64 as well (`native/build.sh --arch all`, clang cross-compile with no sysroot) and packaged at `runtimes/linux-arm64/native`.
- **API compatibility gate.** Every package validates its public API against the last release (`EnablePackageValidation`, baseline 10.0.101.3): a breaking change fails `dotnet pack` unless it is recorded in a suppression file. This release has no breaking changes. The policy, support matrix and deprecation rules are in `docs/VERSIONING.md`, upgrade notes in `docs/MIGRATION.md`, ARM64 status in `docs/ARM64.md`.

- **Vulkan render target** (opt-in: `OPENMAUI_RENDERER=vulkan` or `RendererPreference.Vulkan`). A third GPU target alongside EGL: Vulkan WSI on Wayland and X11, Skia's Vulkan `GRContext` over the swapchain images, the device matched to the compositor's GPU on hybrid laptops (`OPENMAUI_VULKAN_DEVICE` overrides), mailbox presentation so the UI thread never blocks, and the same fallback chain (Vulkan, then EGL, then raster). On native Wayland it is at parity with EGL (2.1 ms average frames at 2240x1400 on Mesa Intel for both); EGL stays the default. Design and numbers in `docs/VULKAN.md`.
- **Native D-Bus desktop portals** (`Services/Portal/`, `docs/PORTALS.md`). Portal calls no longer shell out to `gdbus`: one shared session-bus connection (Tmds.DBus) serves FileChooser (open and save, filters, multiple selection, start folder), OpenURI (URIs, files by descriptor, folders), Notification, Settings (dark mode and accent colour, live through `SettingChanged`, and GNOME text/scaling factors), Inhibit (`DeviceDisplay.KeepScreenOn`), Secret, Background (new `LinuxBackgroundService`), Screenshot and Location (`Geolocation` now returns positions where the desktop provides them). Each service keeps its previous fallback when a portal is missing; `OPENMAUI_PORTALS=auto|prefer|off` sets the policy. Secure storage gains an AES-GCM format keyed from the Secret portal, used only when sandboxed or with `prefer`; existing values stay readable and move to it when next written.
- **Third-party compatibility in the scorecard.** A separate compatibility suite (`tests/Compat`) runs popular MAUI libraries unmodified through the real registration path, and the scorecard gained a "Third-party libraries" section fed from both suites (`--trx` is repeatable): CommunityToolkit.Maui (behaviours, converters, Popup, Expander, AvatarView, DrawingView), CommunityToolkit MediaElement, CommunityToolkit.Mvvm, SkiaSharp.Views.Maui, LiveCharts2, Microsoft.Maui.Controls.Maps, ReactiveUI.Maui, Prism.DryIoc.Maui and Microsoft.Extensions.DependencyInjection page resolution run unmodified; FFImageLoading.Maui has no image service outside Android, iOS and Windows. Syncfusion and Telerik are not evaluated (licence gate).
- **CommunityToolkit `DrawingView`** handler (registered when the toolkit is loaded; OpenMaui takes no dependency on it).

- **Hardware video zero-copy** (MediaElement on the GPU target). When the decoder can export DMA-BUF (the VA-API `va*dec` decoders), frames are imported as EGLImages, NV12 as one external texture converted by the driver, and drawn by Skia with no CPU copy or upload; the import code is shared with the WebView (`Rendering/DmaBufTextureImporter.cs`). Only formats and modifiers the window's EGL display can import are offered; decoders that cannot export DMA-BUF (software, NVDEC) keep the copy path, and any import failure rebuilds the pipeline on the copy path at the same position. On 1080p VP9 (VA-API, Intel UHD 630) process CPU drops 63% (14.7 s to 5.4 s per 25 s of playback) and installing a frame on the UI thread goes from 1.1 ms to 0.1 ms. `OPENMAUI_VIDEO_ZEROCOPY=0` forces the copy path. Details in `docs/MEDIAELEMENT.md`.

- **Benchmark suite and performance gates** (`tools/Benchmarks`, `docs/PERFORMANCE.md`). Headless, one process per scenario, through the real rendering engine on the raster target and a headless EGL context: startup (app build and time to first frame), idle cost (zero frames when nothing changes), memory, scrolling with 1,000 and 10,000 items (and proof of virtualisation), resize, animation through MAUI's ticker, text at 1.0x and 1.75x, and Grid/FlexLayout layout. `--compare` checks a run against `docs/perf-baseline.json` with per-metric thresholds and exits non-zero on a regression (demonstrated with an injected one); the machine fingerprint warns when the baseline came from different hardware. CI runs it in warn-only mode.

- **Sample pages as golden scenes.** Four ShellDemo pages (Typography, Controls, Pickers, About) are inflated from their XAML at runtime with the sample's own theme resources and rendered through handlers, layout and the engine at 1.0x to 2.0x (`tests/Golden/SamplePageSceneTests.cs`): the whole path an app takes is now under pixel comparison, not only individual controls.

- **Syncfusion controls on Linux** (`OpenMaui.Controls.Linux.Syncfusion`, opt-in). Linux apps get Syncfusion's platform-neutral assemblies, whose handlers throw `NotImplementedException` and whose `ConfigureSyncfusionCore()` registers a stub MAUI rejects at startup. Call `.UseLinuxSyncfusion()` in its place (it calls `ConfigureSyncfusionCore()` on the other platforms): every `SfView`-based control (ListView, TreeView, TabView, effects and the rest) lays out through Syncfusion's own code, draws its own `OnDraw` below or above its children, and receives touch, tap, double-tap, right-tap and long-press, fed from OpenMaui's pointer routing into Syncfusion's detectors. Views that only draw (SfTabView's tab-strip border) let clicks through to what is beneath them, as native hit-testing does; SfTabView's pages take the tab view's width (the layout step Syncfusion ships only in its platform builds); and Syncfusion's text measurement, a stub in its platform-neutral build that aborted every tab change, runs on OpenMaui's fonts. Not covered yet: ImageEditor and Syncfusion's MediaElement (dedicated native views). GitCleaner, which uses ListView, TreeView and TabView, now starts with none of the handler failures it logged before.

- **`OPENMAUI_FIRST_CHANCE=1`** logs every exception where it is thrown, with its stack, including ones an app or library catches and reduces to a message.
- **`OPENMAUI_DUMP_TREE=<seconds>`** writes the primary window's view tree (bounds, desired size, MAUI view type, text), modal layers included, to stderr once, that long after startup, and again shortly after each modal page or popup is presented: for diagnosing layout reports without a debugger.

### Fixed

- **Text-heavy frames paused for up to ~50 ms**: font fallback compared typeface family names for every character, and each `FamilyName` read allocates a finalizable SkiaSharp string, so a page of text produced hundreds of thousands of them per frame and periodic garbage-collection pauses. Typefaces are compared by reference now, and the per-run text buffer no longer allocates per character (found by the benchmark suite).
- **CollectionView kept every item view it ever created**: views were created only for rows on screen, but never released, so a long list scrolled end to end held one view per item. Views far from the rows drawn in the last frame are now recycled once the cache grows past a bound; measured row heights are kept, so scroll positions do not move.
- **Seeking landed on the previous keyframe** (`MediaElement.SeekTo`): the seek combined KEY_UNIT with ACCURATE and KEY_UNIT wins, so seeks drifted by up to a GOP (1-2 s on typical HTTP streams, and locally too). Seeks are now exact; each costs the decode-and-discard time (50-470 ms with hardware decode). Seeks also run on a worker, one at a time with the latest target winning, so rapid scrubbing over HTTP can no longer stall a range request and freeze the UI; `Position` reports the pending target meanwhile.
- **MediaElement could abort the process** (heap corruption) when the pipeline was rebuilt: the bus-drain task used a bus the pipeline had already released.
- The hardware decoder preference list now includes the current VA-API decoders (`vah264dec`, `vavp9dec`, ...), not only the older `vaapi*` names.
- **Prism apps started with no window**: startup passed no activation state to `Application.CreateWindow`, so MAUI's window-creator hook, which Prism uses, never ran ("Either set MainPage or override CreateWindow").
- **Wrapping labels ignored `VerticalTextAlignment`**: a Label given more height than its text (the default `LineBreakMode` is `WordWrap`) drew at the top instead of centred or at the bottom.
- **AbsoluteLayout children declared in XAML were laid out at 0x0**: children present before the handler connected never received their layout bounds (it is why LiveCharts drew blank inside an AbsoluteLayout).
- **Fcitx5 input over native D-Bus could never start**: Tmds.DBus cannot build proxies for internal interfaces without seeing the assembly's internals; now granted.
- **D-Bus replies could stall for seconds**: code awaiting a D-Bus call continued on the library's receive loop, so anything that then blocked (the theme service's bounded startup read) held every other reply until its timeout (1.5 s at every start). Continuations now run asynchronously and signal handlers on the thread pool; the theme service starts in about 60 ms.
- `Launcher.Default` (Essentials) passed the unescaped URI to `xdg-open`; it now goes through `LauncherService`.
- **Custom layouts rendered nothing.** A `Layout` subclass without a dedicated handler (a third-party layout such as MarketAlly's `MALayout`, or an app's own) resolved to MAUI's portable LayoutHandler, which throws, so its area stayed blank; where it did reach the platform's generic handler, that handler arranged it as a vertical stack and ignored its `ILayoutManager`. Such layouts now get `CrossPlatformLayoutHandler`, whose view delegates measure and arrange to the layout's own manager through `CrossPlatformMeasure`/`CrossPlatformArrange`, as on the other platforms. Verified against MALayout (header, side and content panes placed and painted).
- **MAUI-side measurement returned 0x0.** `IView.Measure` and `Arrange` go through the handler, and every handler derived from MAUI's portable `ViewHandler`, whose `GetDesiredSize` returns `Size.Zero` and whose `PlatformArrange` does nothing: `view.Measure(...)` in app code, layout managers and templated presenters saw every control as empty. All view handlers now derive from `LinuxViewHandler`, which measures and arranges through the Skia view and honours explicit, minimum and maximum sizes.
- **Shell pages with constructor parameters failed** with "No parameterless constructor". Pages are now built the way MAUI builds them: the page's own registration first (`GetService`, honouring factory registrations), then constructor injection, then the parameterless constructor; services resolve from a window scope (MAUI's `MakeWindowScope`) instead of the root provider; and a failure is logged at Error with the full exception naming the missing dependency (it was a Debug line, stripped from Release builds). The Shell handler's own page path, which had no dependency injection at all, uses the same factory.
- **Errors lost their stack traces.** 52 Error logs across 32 files recorded only `ex.Message` (including the layout handlers' "Skipping child" errors); they now pass the exception.
- **The generated app icon was written next to the executable**, which fails inside an AppImage (read-only mount) and for system-wide installs. An `appicon.png` beside the app is still used when it is current; otherwise the icon is generated once into `$XDG_CACHE_HOME/openmaui/<app>/appicon.png` and reused while it is newer than its inputs. The write also no longer leaves trailing bytes from an older, larger icon (`File.OpenWrite` does not truncate), and the icon scale parses culture-invariantly.
- **`dotnet publish -r linux-arm64` shipped the x86-64 Wayland shim**, so native Wayland could not start on arm64 (the build targets copied the x64 library over the RID-specific one). The copy now honours the RuntimeIdentifier, and builds without one copy the build machine's architecture.
- **Project templates generated projects that failed to load** (MSB4025): the packaging hint in both template `.csproj` files contained `--global`/`--project` inside an XML comment, and XML comments may not contain a double hyphen.
- **`ContentPage.Content` ignored its layout options.** A view set directly as a page's content was always stretched over the whole page; `HorizontalOptions`/`VerticalOptions` of Start, Center and End now place it at its desired size, like any other single-child container. A press on the page area beside such content no longer reaches it (the page forwarded every press to its content).
- Scale detection (`GDK_SCALE`, `QT_SCALE_FACTOR`, gsettings, KDE, Xft.dpi) parsed numbers with the current culture, so `1.5` became 15 under a German or French locale; it is culture-invariant now.
- **`IPlatformApplication.Current` was never set**, so apps that resolve services through it (XAML-created views that cannot take constructor injection, translation markup extensions) failed with "DI container is not available". It is set before the Application is created and exposes the app's services.
- **Images referenced as `.png` did not load when the app ships the SVG.** MAUI's build converts every SVG image to a same-named PNG on the other platforms, so apps write `Icon="save_24dp.png"` for `save_24dp.svg`; on Linux the SVG is copied as is. Buttons, Shell flyout icons, tabs and menu items now fall back to the SVG and render it at the size they draw (`ImageFileResolver`). Icon lookups also no longer use `ImageSource.ToString()`, which returns "File: name.png".
- **`Button.ImageSource` and `ContentLayout` were not mapped**, so image buttons (toolbars) showed text only.
- **Shell flyout icons were missing and hidden items showed as blank rows**: section icons are set when the flyout is built, and `Shell.FlyoutItemIsVisible="False"` is honoured when drawing and hit-testing.
- **"Collection was modified" during layout** when a layout changed its children while being arranged (MALayout moves panes between hosts): child loops iterate a snapshot.
- **Error logs printed only the message.** `DiagnosticLog.Error` now prints the full exception, unwrapped from `TargetInvocationException`/`AggregateException` to the root cause.
- **Cross-platform layouts were arranged in window coordinates.** MAUI hands `CrossPlatformArrange` local bounds starting at (0,0) on every platform, and many layout managers place children from there (Syncfusion's lists do); they now get local bounds, and each child's frame is shifted to window space when its Skia view is placed, including arranges made outside a layout pass.
- **`GraphicsView` drawables drew in window coordinates**: the dirty rect was the view's window position and the canvas was not translated, so a drawable filling `(0,0,w,h)` painted at the window's origin. Drawables now work in the view's own coordinates, clipped to it.
- **Shell pages were wrapped in a scroll view.** Every Shell `ContentPage` was measured with infinite height, so star rows collapsed to their content and a page-filling overlay (an onboarding tour's intro card) was pushed below the window with a scrollbar. A page now fills the content area and scrolls only when the app puts a `ScrollView` in it.
- **Button text had no font fallback**: a character missing from the button's font (the "⋮" of an overflow button, emoji, CJK) drew as an empty box. Labels had fallback but drew a string made only of such characters with the original font; both now use the fallback face.
- **Single-file app icons came out as a purple square.** `<MauiIcon Include="appicon.svg" />` without a `ForegroundFile` is the common form, but only the foreground file was copied beside the app. The MauiIcon file is now the icon's base layer, `BackgroundColor` fills behind it (transparent when unset), the foreground is drawn at `ForegroundScale` and tinted with `Color`, as on the other platforms; offset SVG view boxes are honoured.
- **A desktop entry was never written for apps started from a terminal opened by an AppImage app**: `$APPIMAGE` is exported to everything an AppImage starts, and it alone was taken as proof. The process must now also run from the AppImage's mount (`$APPDIR`).
- **Explicit sizes were lost when a parent measured a view directly.** `WidthRequest`/`HeightRequest` were applied only on the handler path, so a view measured by its Skia parent (a ScrollView's content) was measured against the parent's constraint: a Grid pinned to a width inside a horizontal ScrollView gave its Star columns the wrong width (MAToolbar's `AutoSize` items did not fill the bar), and an Editor with `HeightRequest` could grow past it. An explicit size is now both the measure constraint and the result, as in MAUI.
- **A stopped `ActivityIndicator` stayed on screen** as a frozen ring. It draws nothing when `IsRunning` is false, as on the other platforms.
- **Grids measured with unconstrained width claimed 800 px.** A Grid inside a HorizontalStackLayout or horizontal ScrollView substituted a fixed 800 for the missing width, so its Star columns took 800 px (MAToolbar's end-panel items pushed the bar's `AutoSize` text to nothing and overlapped each other). Star columns now size to their content when the width is unconstrained, as in MAUI's grid, and are re-spread over the arranged width when it differs from the measured one (rows already were).
- **ScrollView content lost its explicit size**: content with a `WidthRequest`/`HeightRequest` was stretched to the viewport.
- **Controls on a tappable layout could not be clicked.** A Grid or Border with a `TapGestureRecognizer` took every pointer event inside it, so the buttons of an overlay with a tap-to-dismiss backdrop (an onboarding tour's Start and Skip) did nothing. A child that handles input itself (a focusable control or a nested tappable view) now keeps it; taps on plain content still reach the container's recognizer.
- **Tappable Borders and Frames raised `Tapped` twice** per tap, the second time at (0,0): the handlers forwarded the view's own tap on top of the one the gesture pipeline raises.
- The theme refresh after a light/dark switch did not reach views inside a ScrollView (its content was missing from the tree walk).
- **Border, Frame and ContentView stretched their content** over the whole inner area, ignoring its `HorizontalOptions`/`VerticalOptions`: a centred Label in a round button drew its text at the top-left. Content is now placed by its layout options, as in MAUI.
- **Labels measured text with their own font only**, while characters it lacks are drawn in a fallback face: text with an emoji (a "📁 20 repositories" status) overran its measured width into the next item, and a label could measure as two lines while drawing one (a stray gap above bold text). Width is now measured per fallback run, the same way the text is drawn.
- **`Shell.ItemTemplate` was ignored**: the flyout always drew its built-in icon-and-title rows. Item templates (on the item or the shell, including DataTemplateSelectors) are now realised per item with the shell item as BindingContext, as in MAUI, so rows can bind `Title`, `FlyoutIcon` and `IsChecked` and react to live bindings; row heights follow the template.
- **`FlyoutWidth` was not applied by the Shell renderer, nor updated at run time**, and widths under 100 px were raised to 100: a flyout collapsed to a 64 px rail kept its full width. The width is applied and tracked (MAUI's -1 still means the default), the content beside a locked flyout is laid out again when it changes, and `FlyoutBehavior` and the flyout header's `HeightRequest` are tracked too.
- **Shell pages raised `Loaded` before their content existed.** The page was parented into the Shell (which gives it a window, and MAUI raises `Loaded` then for a page with a handler) before its content was rendered, so code in `Loaded` that measured the page's views got 0x0 (GitCleaner's stat cards were pinned to zero height). Content is rendered first now.
- **A view's own `MeasureOverride` was skipped** when a Skia layout measured it directly, which is how most layouts measure their children: controls that size themselves there (SfTabView lays out its tabs in it) never saw their size. Views whose type overrides `MeasureOverride` outside MAUI's own controls are now measured through MAUI, as on the other platforms.
- **Grids measured Star-row children against infinite height** before measuring them at their real size, so a virtualising list in a Star row realised every item it had (a Syncfusion list of thousands of commits, on every resize: the window froze). Only Auto rows, or a grid with unconstrained height, measure for natural height now, as MAUI's grid does.
- **`RefreshView` pushed the page down while refreshing** and drew its indicator beneath the content. The indicator now overlays the content during a refresh; only an active pull moves the content.
- **`Dispatcher.Dispatch` ran the action immediately on the UI thread.** MAUI's dispatchers queue it on every platform, even from the UI thread, and code relies on that to run after the current work: a toolbar's "refit on the next tick" ran in the middle of opening its menu and closed it. Dispatch always queues now.
- **Replacing a Shell page's `Content` at run time did nothing on screen.** The page's content was rendered once; controls that open a popup by wrapping the page content in an overlay (MAToolbar's overflow menu) swapped it with no effect. Content changes are followed on the next dispatcher turn, and content that is moved keeps its views.
- **Shell pages had no size** (`Width`/`Height` of -1), so code positioning popups against the page placed them off-screen. The page's frame is set from its host.
- **MAUI frames were window-absolute and only updated when the size changed.** A view's `Frame` (`X`/`Y`) is now relative to its parent and follows moves, as on the other platforms: summing `X`/`Y` up the tree gives the window position, which popups and menus use to anchor themselves.
- **`AbsoluteLayout` mishandled `AutoSize` and proportional sizes**: an AutoSize child was measured 0 wide, and a proportional one was measured with its fraction as a pixel size (a 100% child measured 1 px wide).
- **`MinimumWidthRequest`/`MaximumWidthRequest` (and heights) were ignored** when a Skia layout measured a view directly; they applied only on the handler path.
- **A view coloured only by `BackgroundColor` could paint nothing**: MAUI's default `Background` is an empty, non-null brush, which was taken as set, so `BackgroundColor` was never used (a `BoxView` with a background colour, MALayout's collapse-strip grips).
- **A page with an explicit transparent background was painted opaque**: `Transparent` was treated like "no colour" (the theme's page background), and the page handler dropped it; MAUI's default empty `Background` brush also overwrote the colour. A see-through page now shows what is beneath it, which is how popups presented as modal pages (Mopups on plain net10.0) show the page under them.
- **Screenshots (`Screenshot.CaptureAsync`) left out everything above the page**: modal pages, popups, dropdowns, menus and dialogs are now drawn in, as the window shows them.
- **CommunityToolkit.Maui's `FolderPicker` and `FileSaver` did nothing**: the toolkit's platform-neutral build, which Linux apps get, implements neither, so every call returned an unsuccessful result and "pick a folder" or "save as" silently did nothing. When the toolkit is part of the app, OpenMaui now installs implementations through the toolkit's own `SetDefault`: the desktop portal's native dialog, falling back to zenity or kdialog.
- The folder picker (`PortalFolderPickerService`) now asks the desktop portal first (the desktop's own dialog, and the only one inside a sandbox) and honours the initial folder; zenity and kdialog remain the fallback.
- **Mopups popups crashed Linux apps** (MarketAlly.Dialogs' alerts, toasts, loading dialogs): Mopups' platform-neutral build had no popup platform. When the app uses Mopups, OpenMaui now registers one (MarketAlly.Mopups 3.0.12 takes it from the app's services) that draws popups as window layers without modal navigation, as the native platforms show them: the page beneath gets no Disappearing/Appearing (a page that reloads in OnAppearing kept losing unsaved edits whenever a dialog opened), a click on the popup's transparent backdrop is its background click (close on background click), and with `BackgroundInputTransparent` (toasts) the backdrop lets clicks through to the page.
- **`ListView` was rendered by the CollectionView handler**, which ignores cells, so a ListView of `ViewCell`s (MarketAlly.Dialogs' ActionListDialog) showed no rows. It now gets its own `ListViewHandler`.
- **Tap recognizers ignored `Buttons`**: a left click fired a right-click-only recognizer (a row's context menu opened instead of the row's action), and such a recognizer took the click from the control beneath (an SfListView's ItemTapped never fired). Taps and tap hit-testing now honour the pressed button.
- **A `Border` filled only from `BackgroundColor`**: a brush set through `Background` (a toolbar toggle's checked highlight) was not painted.
- **Labels truncated text that fits**: truncation compared the text's ink bounds with the width, which measuring gives from its advance, so bold text whose glyphs overhang was cut ("Activi..."). Labels measured before they were attached also used the default typeface instead of the app's fonts.
- **`VisualElement.Focus()` threw on every view** ("No result value was set"): the Focus command had no Linux mapping, so an Entry focused from code threw, and Syncfusion's SfListView never raised ItemTapped (its item focuses itself on a tap). A view that can take focus now gets it and `Focus()` returns true; any other returns false, as on the other platforms. `Unfocus()` clears it.
- **Tooltips**: MAUI's `ToolTipProperties.Text` showed nothing. When the pointer rests on an element with a tooltip, or on anything inside it, the text now shows in a small card under the pointer, drawn over the window's content; it hides when the pointer leaves, on a press or scroll, and when the window loses focus.
- **Hovering a Button, ImageButton, CheckBox, RadioButton, Stepper or Picker never reached a `PointerGestureRecognizer`**, on the control or on a view around it: those controls handled pointer enter and exit themselves without passing them on. Hover-driven UI around a button (MarketAlly.MAToolbar's rich tooltip cards) now works.
- **A margin shrank a child in a Grid's Auto row or column, and an AbsoluteLayout AutoSize child**: the cell was sized to the child without its margin, then the margin was taken out of it, so a button with a 4 px margin came out 4 px narrower than its neighbours. Cells now hold the child and its margin, and children are measured at the cell size less their margin, as on the other platforms.
- **Maximum and minimum sizes bound the measure, not only its result**: a `MaximumWidthRequest` card of wrapping text was measured as one long line and then narrowed, so its text wrapped into a height sized for one line and was clipped. The constraint is now clamped first, as MAUI does.
- **A layout change made during layout showed a frame late**: a page laid its content out while drawing, and a change asked for in a `SizeChanged` handler (a tooltip card or menu placing itself) was drawn at the old position for one frame before moving. Pages lay out in the layout pass, and the renderer re-runs layout (up to twice more) until no more changes are asked for before drawing.
- **CollectionView rows had a 44 px minimum height**: a CollectionView row is as tall as its template on every platform, so a diff of short lines was spread out. The 44 px is now only the estimate for rows not yet measured; a ListView keeps its row height.
- **`IsClippedToBounds` did not clip**: children of a clipped layout drew outside it. SfTabView slides its pages in a clipped strip, so the next tab's page showed beside the current one.
- **Picker text ran past the control**: a selected item longer than the picker drew under the arrow and beyond the edge; it is now trimmed with an ellipsis, in the closed picker and in its list.
- **No alert, action sheet or prompt showed in a Shell app**: the renderer drew the Shell and its pages without MAUI handlers. MAUI connects a window to its alert system when the window's page gets a handler, and holds a page's `DisplayAlert`, `DisplayActionSheet` and `DisplayPromptAsync` until the page has one, so the requests never showed and the awaiting code never resumed (MarketAlly.MAToolbar's grouped and compressed dropdowns opened nothing). The Shell and its pages now get a handler over the views the renderer draws.
- **The action sheet fits the window**: a long list ran off the bottom of the window, title and cancel included, with no way to scroll or dismiss it. The options are now a compact list that scrolls (wheel, or the keyboard highlight) between the pinned title and cancel button, and a click outside the sheet dismisses it as cancel, as on iOS and Mac Catalyst.
- **An AbsoluteLayout ignored a child's `LayoutBounds` changed after it was added**: the bounds were copied when the child was added. MAToolbar places its overflow menu below its button and moves it above once it knows its height; the move was lost, so the menu opened downward off a bottom toolbar with its last item clipped.
- **A Grid shrank a child with an explicit size to a smaller cell**: MAUI keeps the explicit size and places it by its alignment, and the parent's clip does the cutting. SfTabView's page strip, as wide as all its pages, was cut to one page, so every tab after the first was blank.
- **An empty CollectionView took room and showed "No items"**: a CollectionView or ListView asked for all the room it was offered (300 px when unbounded) and drew "No items" when empty. As on the other platforms it now asks for its content's height, up to the room offered (a Star row or Fill alignment still stretches it), and shows nothing when empty unless an `EmptyView` is set; a Grid's Auto row holding an empty list is 0 tall instead of taking the grid's whole height.
- **No caret in an empty Entry or Editor with a placeholder**: the placeholder was drawn instead of the caret, so clicking into an empty search box showed no sign of where typing would go. The caret now shows in front of the placeholder, as on the other platforms.
- **Scrolling a ScrollView did not report its position**: `ScrollX`/`ScrollY` stayed at 0 and `ScrollView.Scrolled` never fired, so code that follows the scroll saw nothing, and controls that create their rows as they scroll into view (Syncfusion's SfListView) showed only the rows of their first screen. The position is now reported as on the other platforms, and `ScrollToAsync` completes even when the view is already at the target.
- **`ZIndex` was ignored**: overlapping children were drawn and hit-tested in the order they were added, so a view raised with `ZIndex` could end up underneath its siblings. SfListView keeps its sticky group headers above the rows scrolling beneath them with `ZIndex`, and the rows painted over the header whenever they had been added after it. Children now draw, and take the pointer, by `ZIndex` (in child order within the same ZIndex), as on the other platforms.
- **Syncfusion: rows showed through a translucent sticky group header**: SfListView clips each row where a sticky header covers it. Its platform-neutral build ships the step that computes the clip (`ApplyClip`) empty, although the computation itself (`ApplyListViewItemClip`) is in it, and leaves applying the clip to the native view. The Syncfusion bridge now patches the empty step to run the computation and applies the resulting `ClipRect` to the row's drawing and hit-testing, so the header shades the list background as on the other platforms.
- **`Shell.FlyoutContent` was not shown**: a Shell whose flyout is its own view (`FlyoutContent` or `FlyoutContentTemplate`, typically a navigation rail with the standard items hidden) showed an empty flyout. The view now replaces the item list between the flyout header and footer, and takes input, as on the other platforms.
- **A margin shrank a child in a StackLayout**: as in the Grid, the stack sized each child without its margin and then took the margin out of it, so a 1 px separator with a 4 px margin became a thick bar (MarketAlly.MAToolbar's menu separators) and labels with a top margin sat on the view above them. The margin now goes around the child.
- **Replacing a layout's child did not replace it on screen**: `Layout[i] = view` (the `Update` command) only re-laid the layout out, so the old view stayed. `BindableLayout` swaps its rows this way when its `ItemTemplate` changes, so rows kept their old template (MarketAlly.Foundation's flyout footer kept its full rows in rail mode). The platform child is now replaced.
- **A CollectionView kept rows made from its previous ItemTemplate**: a template set at run time applied only to rows not yet created, so the list stayed one template behind. The rows are now rebuilt from the new template.
- **A ContentView ignored its content's margin and its own padding when measuring**: the content was placed without its margin (MarketAlly.Foundation's rail header, whose top margin clears the rail toggle, drew its image over the toggle) and the ContentView asked for no room for either. Both now count, as in MAUI.
- **A Grid ignored a child's Row, Column or span changed after it was added**: they were copied when the child was added. They are now read when laying out (Foundation's rail settings chip, which spans both columns once folded, sat in the first column).
- **Line breaks in alert and prompt text showed as boxes**: `DisplayAlert`, `DisplayActionSheet` and `DisplayPromptAsync` wrapped their text by words only and drew `\n` as a missing glyph. Line breaks now start new lines, and a blank line stays blank.
- **Syncfusion Charts did not show**: every chart type derives from `ChartBase`, an `IContentView` that MAUI resolved to its stock ContentViewHandler, which has no platform view in the platform-neutral build and threw. The Syncfusion bridge maps `ChartBase` to OpenMaui's ContentView handler, and OpenMaui's ContentView now lets a view that lays itself out (`ICrossPlatformLayout`, other than a plain ContentView) measure and arrange its content, as the other platforms' content panels do.
- **A layout's own `ArrangeOverride` did not run under a Skia parent**: library layouts that place their children there (Syncfusion's chart `LegendLayout` sizes the chart area around the legend) were arranged natively instead, so the chart area kept its default size. As with `MeasureOverride`, such a view is now arranged through MAUI.
- **Syncfusion text drawing threw**: `CanvasExtensions.DrawText`, a stub in Syncfusion's platform-neutral build, threw `NotImplementedException`, aborting the paint of every view that draws text through it (chart axis and data labels, and the axis lines drawn with them). The Syncfusion bridge implements it on MAUI's `ICanvas.DrawString` with the element's font, size and colour, and supplies the default text size the chart tooltip and SfBusyIndicator threw for.
- **Animations through the app's services never ran**: MAUI's `UseMauiApp` registers its own animation ticker, which never runs on the platform-neutral build, and OpenMaui's registration, added only if none existed, lost to it. Anything that animated through the app's `IAnimationManager` got no frames; Syncfusion schedules chart and list updates as one-frame animations, so charts never plotted their data. OpenMaui's ticker and animation manager now replace MAUI's. An app or test host that supplies its own `ITicker`/`IAnimationManager` (a fake clock) registers it after `UseLinux()`, which replaces any registered before it.
- **An idle window kept the UI thread busy**: the renderer measured and arranged the whole tree on every loop turn, dirty or not. Layout now runs only when something asked to be repainted (every layout request does), and a library layout that re-plots whenever it is arranged (Syncfusion's chart) is no longer re-arranged when neither its bounds nor its layout changed; this ended a chart repainting itself forever and a Syncfusion-heavy page using a full core. MAUI's `InvalidateMeasure` command now reaches the platform view, so a control that changes still gets laid out.
- **Syncfusion repaint requests were dropped**: `SfView.InvalidateDrawable` and `SfDrawableView.InvalidateDrawable` only reach Syncfusion's own handler types. The Syncfusion bridge now routes them to its platform views, instead of repainting every Syncfusion view on every animation frame to catch changes it could not see, and draws through one reused canvas instead of a new one per view.
- **Syncfusion Charts: every series type and interaction.** The platform-neutral build leaves out steps the charts need: `CanvasExtensions.DrawLines` is empty (FastLineSeries and a histogram's distribution curve drew nothing) and now strokes the points as a polyline; FastLineSegment never recorded its first point, so the line started at the second; `ChartZoomPanBehavior.SetTouchHandled` is empty, so a pannable chart now marks its touch handled from press to release as on Windows. Pie, doughnut and radial-bar wedges draw whole (see the arc fix below). Tooltips, trackball, crosshair, selection, zoom and pan (drag, mouse wheel, ctrl+wheel pinch) work.
- **Arcs in MAUI Graphics paths did not join the current point**: MAUI Graphics' Skia conversion turns `PathF.AddArc` into a new contour, where CoreGraphics, Win2D and Android connect the arc to the point before it. A wedge (MoveTo the centre, AddArc, Close) drew as an arc closed by its chord in any GraphicsView or `IDrawable`, Syncfusion's pie, doughnut and radial-bar charts among them. Paths with arcs are now converted with each arc joined to the point before it.
- **Syncfusion controls with their own native views** now work: SfCarousel (the fanned Default mode and the Linear strip, swipe, click and animated selection), SfRotator, SfSignaturePad (drawing, `ToImageSource` and `GetSignaturePoints`) and SfInteractiveScrollView, whose platform views were stubs in the platform-neutral build, are supplied by the Syncfusion bridge.
- **Syncfusion SfComboBox and SfAutocomplete drop-downs** never opened: the native builds show them in a native popup whose platform-neutral handler is empty. They now open in an overlay anchored to the control, draw their items, close on a press outside, and take Up, Down, Enter, Escape and Tab from the control.
- **Syncfusion keyboard, pinch and drag positions.** Controls with Syncfusion keyboard detectors (SfListView, SfTreeView, SfRating, SfSwitch, the DataGrid and others) take focus when pressed and hear keys routed the way WinUI routes them (preview from the root down, then bubbling up to the first handler); ctrl+wheel pinches; and the point conversions list, tree and scheduler drag-and-drop compute from (`GetRawPoints`, `GetContainerPoints`, stubs returning 0,0) now return real positions, so a dragged row follows the pointer. Core: a view's key events can be observed and handled along its ancestors (`SkiaView.KeyRouted`), the wheel reports its modifier keys on X11 and Wayland, and touch points in a scrolled Syncfusion list no longer drift by the scroll offset.
- **Syncfusion: SfPopup and the controls that open one** (dialog-mode Picker and Calendar, RichTextEditor dialogs, Toolbar overflow, Scheduler and DataGrid dialogs) now show. Syncfusion's window overlay, empty in the platform-neutral build, is hosted as a window-wide overlay: the popup appears centred, at a position or next to a view, with its overlay colour or a blurred page beneath, its background, rounded corners and shadow, and its open and close animations; its buttons and content take input, a press outside closes it unless `StaysOpen` is set, and it re-centres when the window resizes.
- **Grid columns or rows added after the grid was shown were ignored**: MAUI only invalidates a grid's measure when its existing definition collection is cleared or added to, so the platform grid kept its old definitions. It now picks the definitions up when it measures. SfPopup's two-button footer, built this way, placed both buttons in one column, with the decline button past the popup's edge.
- **Popups drew above where they took input on Wayland with client-side decorations**: pickers, drop-downs and Syncfusion popups were drawn without the title bar's offset that their pointer input already had, so each appeared 32 px higher than where it was clicked.
- **Every window resize laid the page out at the wrong width first**: the resize handler measured and arranged the tree at the buffer's physical size, and the frame then laid it out again at the logical size. On a scaled display every view went through a pass at the scale factor times its width on each resize step and straight back, so a layout that reacts to its width (a toolbar folding its items to icons) re-fitted twice per step while the window was being resized. The tree, and any modal layer, is now laid out at the logical size, below a client-drawn title bar, as the renderer lays it out.
- `OPENMAUI_TRACE_INVALIDATE=1` logs, once a second, how many frames were drawn (and how many whole) and which views asked to be repainted, for finding what keeps an idle window busy.
- **List separators**: every vertical CollectionView drew a light hairline under each item (bright in dark mode). A MAUI CollectionView has no separators on any platform; a ListView now draws them per `SeparatorVisibility` in its `SeparatorColor`, with a theme hairline by default.
- README: the Fedora package for the GStreamer libav plugin is `gstreamer1-plugin-libav` (`gstreamer1-libav` is the RPM Fusion name).
- **WPE availability was misstated.** The README, roadmap, BlazorWebView's error message and the doctor said Debian and Ubuntu ship `libwpewebkit-2.0-1`. Ubuntu has published no WPE WebKit package since 22.04, and Debian 13 carries 2.48, older than the 2.54 the WebView needs; only Debian testing and sid have 2.54. On those systems the WebView uses WebKitGTK in GTK mode and BlazorWebView needs a WPE 2.54 from elsewhere; the docs, hints and the support matrix (`docs/VERSIONING.md`) now say so.

### Fixed

- **Views inside layouts never received the render context.** `SkiaLayoutView` (and other containers) keep their own child lists, so the engine's `RenderContext` set on the root never reached descendants; they fell back to `SKTypeface.Default`, which silently ignored `FontFamily` and `FontAttributes`: italic text rendered upright and bold was synthetic emboldening rather than the family's bold face. - **Font fallback cache conflated styles.** `FontFallbackManager` cached "which typeface renders this codepoint" by family name only, so after a regular label had been drawn, italic and bold labels of the same family were handed the regular face. Keyed by typeface instance now.
- Essentials services (found by the new tests): `Map` formatted latitude/longitude with the current culture (`48,85` under a German locale) and `TryOpenAsync` always returned true; `Launcher` passed the unescaped URI to `xdg-open` (spaces broke it); `PhoneDialer` and `SMS` escaped `+` to `%2B` in `tel:`/`sms:` URIs (invalid per RFC 3966/5724) and `SMS` appended an empty `?body=`; `Email` encoded `@` as `%40` in addresses (RFC 6068 keeps it literal); `FilePicker` faulted its task when `FileTypes` was set (evaluated outside the try on the portable Essentials build); `Battery` reported `PowerSource.Battery` on desktops with no battery (now AC, and a `Mains` supply with `online=1` is honoured); `DeviceDisplay` parsed `GDK_SCALE`/`QT_SCALE_FACTOR` with the current culture; `Flashlight.TurnOnAsync` silently did nothing without a torch (now `FeatureNotSupportedException`, as documented); `AppActions` resolved `$XDG_DATA_HOME` once at type load.

- **`SkiaCollectionView.SelectedItem` set from code looped forever.** The property-changed handler wrote the property back through `SelectItem`/`ClearSelection`; `BindableObject` defers re-entrant sets of the same property until the outer set returns, so the deferred writes fired after the re-entrancy guard was released and ping-ponged with the handler. Programmatic selection now mirrors into the selection state without writing the property.

## [10.0.101.2] - 2026-09-20

### Added

- **WPE WebKit WebView** (`Views/WpeWebView.cs`, `Handlers/WpeWebViewHandler.cs`). The pointer follows the page (hand over links, I-beam over text) by surfacing WPE's cursor requests to the platform cursor.
- **Permissions, web notifications, downloads, spell checking in the WebView.** Geolocation, camera/microphone/screen and notification permission requests are asked through the platform's confirm dialog (anything else is denied); the Web Notifications API is routed to the platform notification service; downloads save into `~/Downloads` under the suggested name (made unique) with a completion/failure notification; spell checking is enabled for the user's locale (red underlines and a "Spelling Suggestions" group in the context menu when enchant and a dictionary are installed). Context-menu submenus are flattened into the platform menu as a header plus indented items. Double and triple clicks now carry a click count, so word and paragraph selection work.
- **Clipboard bridge.** The headless WPE platform has an in-process clipboard; the view syncs it with the system clipboard in both directions (Copy/Cut out via change-count tracking; system text in on focus, secondary click and Ctrl+V) so copy and paste behave like a browser.
- **`WebKitContentApi`** (`Native/WebKitContentApi.cs`, public). The WebKit GLib content API shared by the WPE and WebKitGTK ports (custom URI schemes with per-view routing, user scripts, script-message handlers, `evaluate_javascript`) resolved by symbol from a given library, so bridges are written once.
- **`OpenMaui.Controls.Linux.Blazor`** (new opt-in sibling package). Linux backend for `Microsoft.AspNetCore.Components.WebView.Maui`: `.UseLinuxBlazorWebView()` registers `LinuxBlazorWebViewHandler` over the WPE view with a `WebViewManager` that serves the app through the `app://localhost/` scheme (WebKit rejects `0.0.0.0` as a restricted host), bridges JavaScript messages through a WebKit script-message handler, starts Blazor once the bridge exists (`autostart="false"` host pages), embeds `blazor.webview.js` from the exact framework version it compiles against, serves an empty JS-initializers manifest when the app has none, and raises `BlazorWebViewInitializing`/`Initialized` and `UrlLoading` (external links open in the system browser by default). - **Spike records.** `docs/WPE-EMBEDDING.md` with the verified embedding sequence and pitfalls, plus the C probes (`wpe-headless-probe.c`, `wpe-click-probe.c`).

- **`IRenderTarget` seam** (`Rendering/IRenderTarget.cs`). `SkiaRenderingEngine` no longer owns pixels; a target provides the canvas (`BeginFrame`) and submits the frame (`EndFrame`). `RasterRenderTarget` is the historical path (bitmap -> `IDisplayWindow.Present` -> wl_shm / XPutImage); the engine's default constructor still uses it, so existing tests and callers are unchanged. `PreservesContents` tells the engine whether partial repaints are valid.
- **EGL render targets.** `WaylandEglRenderTarget` (wl_egl_window over the native wl_surface) and `X11EglRenderTarget` (EGL config matched to the window's visual). EGL 1.5 platform display, OpenGL ES 3 with ES 2 fallback, Skia `GRContext` on the default framebuffer, `eglSwapBuffers` presentation with swap interval 0 so a hidden window never blocks the run loop. One context per window, made current per frame, disposed before the window's display connection closes.
- **Renderer selection with fallback.** `RenderTargetFactory` tries the GPU target and falls back to raster on any failure (missing libEGL, software-only drivers, headless). `LinuxApplicationOptions.Renderer` (`Auto` default, `Gpu`, `Raster`) and the `OPENMAUI_RENDERER=gpu|raster|auto` environment variable override it; an explicit `gpu` that fails logs an error and still runs on raster. - **Frame statistics.** `OPENMAUI_RENDER_STATS=1` prints, per window every two seconds, rendered frames, effective FPS and average / p50 / p95 / p99 / max frame time (draw + flush + submit). Only rendered frames count, so idle loops show nothing.
- **`WaylandWindow.ExternalPresentation`** and `IWaylandSurface`. When a GPU target owns the surface the window releases its wl_shm buffer and stops attaching it from `Show`/`Present`; the wp_viewporter destination it already maintains keeps buffer size physical and the compositor-visible size logical, so fractional scaling is unchanged.

### Fixed

- **Wayland event loop could stall with a second event queue.** `DispatchReadEvents` used `wl_display_dispatch`, which blocks until an event for the default queue arrives even when the readable data was entirely another queue's (Mesa's EGL buffer-release and frame-callback events). With the GPU target active the app froze after the first frames until the next input event. Replaced with the `wl_display_prepare_read` / `read_events` / `dispatch_pending` sequence, which reads once, demultiplexes, and returns.
- **Idle repaint on non-preserving targets.** The engine's "nothing dirty" early-out is now evaluated before the full-versus-partial decision, so a GPU target does not repaint every loop iteration.

### Known gaps (WPE WebView)

- Keyboard events carry no hardware keycode (pages reading `event.code` see none). Frames are copied to a bitmap per frame (the DMA-BUF to EGLImage zero-copy path on the GPU target is the next step).

### Changed

- WebView tests: `tests/Views/WpeWebViewSupportTests.cs` covers keysym translation (printable and control keys, round trip) and backend selection.

> The multi-window release, on a fully migrated rendering stack. Aligned to MAUI 10.0.101, which forces the SkiaSharp 3 → 4 major-version jump (the legacy `SKPaint` text APIs are error-obsolete in 4.x — nearly 400 call sites across ~30 files migrated to the `SKFont` API). ### Added

- **Multi-window support.** `Application.Current.OpenWindow(new Window(page))` now works: each MAUI `Window` gets its own native toplevel (X11 and Wayland at full parity — each window owns its display connection), its own Skia rendering engine, and its own input routing with independent focus/hover/capture, all through the `Guarded` exception containment. A new `WindowContext` registry backs it; the legacy single-window members forward to the primary context so existing consumers are unchanged. `IWindow` lifecycle (`Created`/`Activated`/`Deactivated`/`Destroying`) fires per the MAUI contract — `Activated`/`Deactivated` follow OS focus. Closing the primary window keeps the app alive while secondaries remain; the app exits when the last window closes. `Application.CloseWindow` works. The Application handler is now attached at startup (it never was on this platform, so `OpenWindow` used to silently no-op). Per-window routing decisions for shared services are documented in code: Wayland clipboard follows keyboard focus, dialogs/context menus are app-modal and latch to the focused window, popup overlays are filtered per window, theme changes refresh every window. V1 scope notes: drag-and-drop targets the primary window; GTK mode remains single-window; title/page changes to an already-open secondary don't propagate; `IWindow.Stopped`/`Resumed` and window positioning are deferred.
- **Hot Reload for non-Shell roots.** A raw `ContentPage`/`NavigationPage` window page now structurally reloads under `dotnet watch`: the root page type is rebuilt (DI-first), re-parented into the MAUI Window, re-rendered, and swapped with correct `Disappearing`/`Appearing` lifecycle. NavigationPage stacks reset to the rebuilt root on structural reload — verified to match MAUI's own hot-reload behavior. Plain `new NavigationPage(page)` roots re-wrap the rebuilt inner page, preserving code-set bar styling.
- **Async image sourcing for outgoing drags.** `StreamImageSource` images now work as drag payloads: the drag still starts synchronously (press-serial constraint), while the stream is read in-flight (`DragPayload.PendingImage`); transfer paths await it with a 5 s bound and honest-fail just the image MIME on timeout (text/files in the same payload still deliver). Image format is sniffed from the stream header (PNG/JPEG/GIF/WebP/BMP) rather than assumed; a MIME mismatch fails cleanly instead of serving mislabeled bytes. On X11, not-yet-resolved image requests defer the `SelectionNotify` on the event pump instead of blocking it.

### Changed

- **Aligned to .NET MAUI 10.0.101; SkiaSharp 3.119.2 → 4.152.1** (forced by MAUI's dependency floor), with HarfBuzzSharp 14.2.1.201, Svg.Skia 5.2.3, and CommunityToolkit.Maui.MediaElement 9.0.0 → 10.0.0 (the MAUI-10-aligned toolkit; the Linux handler required no changes). All five packages move to `10.0.101.1` in lockstep. The SkiaSharp 4 migration: every legacy `SKPaint` text member (`TextSize`, `Typeface`, `TextAlign`, `MeasureText`, `FakeBoldText`, `FilterQuality`, the `SKPaint(SKFont)` constructor, paint-only `DrawText`) is `[Obsolete(error: true)]` in 4.x — all call sites moved to `SKFont`-based measurement/drawing and `SKSamplingOptions` (legacy High quality → Mitchell cubic), preserving rendering behavior.
- **New `SkiaFontFactory` — the single construction path for SKFonts** (`Subpixel = true`, `LinearMetrics = true`). Required on DPI-scaled canvases: SkiaSharp 4's font defaults snap glyph advances to integers in font space, and the HiDPI canvas scale magnified the rounding into visible intra-word gaps ("SearchBar" rendered as "Search Bar" at 2x). All rendering/measurement code must create fonts through the factory — mixed settings cause measure/draw mismatch.

### Fixed

- **Wrapped labels no longer overdraw their siblings.** `SkiaLabel.MeasureOverride` measured soft-wrapped text as a single line (it never consulted the available width), so a wrapping label under-reported its height and its extra lines drew over the next control. Measurement now mirrors the draw path exactly: same wrap condition, same `WrapText`, same line-height math, capped by `MaxLines`.
- **Label heights are glyph-independent.** Single-line labels measured height by ink bounds, so "Input" (descender) measured taller than "Buttons" and sibling spacing shifted with the letters in the text. Height now comes from the line height (`FontSize × LineHeight`, default 1.2), consistent with the multi-line branch and other MAUI platforms.
- HiDPI intra-word glyph gaps (see `SkiaFontFactory` above) — text on scaled canvases renders with correct kerning and even spacing again.
- **No more dead launcher entries when running from an AppImage.** `InstallDesktopEntry` wrote a `.desktop` file whose `Exec` pointed into the AppImage's ephemeral FUSE mount (`/tmp/.mount_*`) — a broken launcher icon after every run, duplicating the AppImage installer's own entry. The platform now detects `$APPIMAGE` and skips its desktop entry, leaving desktop integration to the AppImage's first-run installer.
- **Closing a WebView app no longer crashes (SIGSEGV) on exit.** Teardown fired a focus-lost invalidation (`WindowContext.Dispose` → `FocusedView = null` → `OnFocusLost` → `RequestRedraw`) into the already-destroyed GTK host window (`gtk_widget_queue_draw` on a freed widget). Root-cause diagnosed from the core dump. Dispose now drops focus/hover/capture silently; every GTK widget pointer is zeroed via its `destroy` signal and all GTK entry points guard on zero; WebView navigation/theme idle sources are tracked and removed on disconnect. Also fixed a latent same-class bug: `SkiaWebView` released its GTK toplevel with `g_object_unref` instead of `gtk_widget_destroy`, leaving the window and WebKit child alive in GTK's toplevel list after managed code considered them gone.
- **Returning to a list page no longer flashes.** Two frame-ordering defects: (a) after an `ItemsSource` refresh, the first frame laid rows out at the default height and a corrective frame re-laid them at measured heights — items are now measured before row positions are computed, so the first frame is final (also fixes the same flash on theme switches); (b) on animated push/pop, `OnAppearing` fired after the animation settled, making appearance-time refreshes visible — it now fires before the page is presented, matching the other MAUI platforms. Note: apps now receive `OnAppearing` before the transition animation instead of after it.
- **Vertically centered text no longer drifts with its glyphs.** 32 sites across 16 controls (buttons, entries, pickers, nav bars, collection views, dialogs, tab bars, the CSD titlebar) centered text by its ink bounds, so strings with descenders sat visibly higher than strings without ("Play"/"Stop" vs "Pause"/"Mute" on MediaDemo's buttons). All converted to the new `TextRenderingHelper.BaselineForVerticalCenter` (font-metrics based, glyph-independent). Standalone symbol glyphs (stepper +/−, font-icon images) intentionally keep optical ink-centering.

> Two-part release. First, stability and correctness hardening across the 10.0.70.x surfaces, driven by a deep code review of the newest subsystems — several crash-class and data-corruption-class bugs fixed. Second, a desktop-integration round-out: full X11 XDND drag-and-drop in both directions, IME surrounding-text, map polygon/circle overlays, a GTK print dialog, and an XEmbed tray fallback.

### Added

- **Outgoing drags on X11, and a backend-agnostic entry point.** `DragDropService.TryStartDrag(text)` routes to the native Wayland data-device drag when available and otherwise runs a full XDND source: XdndSelection ownership, pointer grab, `XdndAware` target discovery under the cursor, Enter/Position/Status negotiation, drop + `SelectionRequest` data delivery (`TARGETS`, `UTF8_STRING`, `text/plain` variants), Escape cancel, and 2 s finish timeouts. (Incoming X11 drops are under Fixed below.)
- **`GetPosition(relativeTo)` returns real view-relative coordinates** on every gesture args type (tap, swipe, pan, pinch, pointer, drag-starting, drag-over, drop). The position resolvers previously ignored the `relativeTo` element and always returned the window point; one shared resolver now translates against the target view's `ScreenBounds` (scroll-offset correct), returns the window point for `null`, and returns `null` for unresolvable elements per the MAUI contract. Also fixed the args-constructor selection that preferred `DragEventArgs`' resolver-less overload, which would have silently dropped positions.
- **MAUI drag/drop gesture recognizers now work.** `DragGestureRecognizer`: press + move past the pan threshold on a `CanDrag` view fires `DragStarting` (honoring `Cancel`), extracts the `DataPackage` text, and starts the native drag — previously drag-gesture detection didn't exist on this platform at all. `DropGestureRecognizer`: native drags are hit-tested to the drop-target view with correct per-view enter/leave/over transitions (repeat-fire `DragOver`, tracked on the recognizer owner so child crossings don't flap), `Drop` delivers text and file paths (`DataPackage.Properties["FilePaths"]`), `AllowDrop` and `AcceptedOperation == None` are honored and fed back to the native layer (`wl_data_offer.accept(NULL)` / `XdndStatus(accepted=0)`). Drop events now carry window coordinates on both backends (X11 XdndPosition root coords translated + DPI-scaled to match pointer dispatch). `DragDropService.Default` events keep firing unchanged — the gesture routing is additive. MAUI-internals access is cached reflection with graceful degradation; a MAUI signature drift logs and disables recognizer delivery without affecting the native protocol or service events. File/image payload *sourcing* for outgoing drags remains a TODO (text only).
- **`set_surrounding_text` — the IME loop is complete.** The focused `SkiaEntry`/`SkiaEditor`'s text, caret, and selection anchor are now pushed to the compositor via `zwp_text_input_v3` (≤4000-byte UTF-8 window centered on the caret, cut on code-point boundaries; spec-correct `set_text_change_cause`; pushes coalesced per frame and deduped; password entries excluded). The same read seam also feeds IBus via `ibus_input_context_set_surrounding_text` (code-point offsets), so X11 IME users benefit too.
- **Map polygon and circle overlays.** `LinuxMapHandler` now routes `IFilledMapElement` (polygons) and `ICircleMapElement` (circles) in addition to polylines — fill + stroke honored, circle radius projected through Mercator meters-per-pixel at the center latitude, world-wrap aware. `SkiaMap` gains `Polygons`/`Circles` collections (new `MapPolygon`/`MapCircle` types) for code-first use.

Installs a process-global X error handler (chaining to any prior one) so a dying tray manager can't terminate the app.
- Legacy map tile-cache directories (pre-provider-keyed layout) are deleted by the startup sweep instead of lingering until the size cap reaches them.

### Fixed — Shell page lifecycle

- **`OnAppearing`/`OnDisappearing` now fire under Shell navigation.** They never had: `SkiaShell` swapped page content without sending lifecycle events, and even when sent, MAUI's `Page.SendAppearing` silently no-ops unless the page's parent chain reaches an Application-attached Window — which renderer-created pages never had. Three-part fix: `SkiaShell` tracks the current MAUI page and sends `Appearing`/`Disappearing` on section navigation, push/pop/pop-to-root, and theme-refresh re-renders; `LinuxViewRenderer` parents every page it creates into the real Shell hierarchy via `ShellContent.ContentCache` (which also populates `IShellContentController.Page`); and the initial page's Appearing is re-issued once the shell is fully attached, covering the startup ordering race. Any page that subscribes/unsubscribes event handlers in these overrides — a core MAUI pattern — now works.

### Fixed — Wayland core

- **All Wayland listener callback delegates are now rooted in fields.** Every listener registration (registry, seat, xdg_surface/toplevel, wm_base, buffer, decoration, fractional-scale, text-input, pointer, keyboard, data-device, primary-selection device) previously passed unrooted delegate temporaries to `Marshal.GetFunctionPointerForDelegate`; after any GC the native thunk was freed and the next compositor event jumped into freed memory. Repo-wide sweep; zero unrooted callback sites remain.
- **Drag sources are destroyed on `dnd_finished`.** A successful outgoing drag previously never cleaned up its `wl_data_source` — leaking the proxy and, worse, leaving the clipboard's self-paste short-circuit pointing at the dragged text (copy "A", drag "B", paste → "B"). Drag sources now have their own tracking, fully separate from clipboard selection bookkeeping.
- **`DragEventArgs.Accepted` now defaults to `true`.** Drops were silently rejected unless a `DragEnter` handler explicitly opted in, making DnD inert out of the box on both backends.
- **DnD protocol correctness:** rejection now sends a NULL mime (empty string is a *real* accept on the wire and could make source apps delete "moved" data); enter with a null offer no longer crashes; enter/motion coordinates are converted from `wl_fixed_t` and DPI-scaled (were 256× too large); `set_actions`/`finish` are gated on the actually-bound `wl_data_device_manager` version; `start_drag` uses the button-press serial (stale serials made compositors silently ignore drags); drop processing captures the offer and accepted mime before clearing shared state, closing races with late `leave` events and back-to-back drags.
- **Self-paste deadlock fixes:** `PrimarySelectionService.HasText` and `ClipboardService.HasText` were sync-over-async — freezing the GLib loop and, when our own process owned the selection, deadlocking permanently. Both are now zero-I/O probes of tracked native state. Pipe writes to paste requesters moved off the main thread; `receive()` reads re-validate the offer on the main thread and read on a background thread with an idle-based timeout that returns failure (engaging fallbacks) instead of silently-empty text. The self-paste short-circuits also dispatch pending events first, so a just-lost selection isn't answered with stale text.
- Primary selection can now be **cleared** (`SetTextAsync(null)` → `set_selection(NULL)`), and `TrySetPrimarySelectionText` fails gracefully when protocol symbols are missing.

### Fixed — X11

- **First working XDND drop path.** The XDND handlers existed but were never driven; `RequestDropData` was a stub that returned null while acking success — a source app performing a Move could delete the user's file with nothing delivered. The X11 window now announces `XdndAware`, routes `ClientMessage`/`SelectionNotify` into `DragDropService`, and implements the real transfer: `XConvertSelection` → `SelectionNotify` → property read (INCR-capable for large payloads) → `XdndFinished` reporting success only when data actually arrived.

### Fixed — Maps

- **Tile-cache images can no longer be disposed while the renderer is drawing them** — eviction/replacement disposal is deferred to a future main-loop iteration.
- **`MoveToRegion` now lands on the requested span.** The span→zoom conversion ignored viewport size (correct only for a 256-px-wide map; a 1280-px window under-zoomed by ~2.3 levels). Pre-layout calls are deferred until first layout.
- **`Map.VisibleRegion` is now written back** after pan/zoom (was permanently null), with reentrancy guards; `VisibleRegion` removed from the input property mapper.
- Marker vs info-window click semantics now match other platforms (first tap selects + `MarkerClicked`; tapping the selected pin fires `InfoWindowClicked`); pin hit-testing works inside scrolled containers; pins/polylines render (and hit-test) in wrapped world copies across the antimeridian; pan clamps at the Mercator latitude limit instead of sticking past the pole; mutating a `Pin` in place (Location/Label) now updates its marker.
- **Tile service hardening:** downloads capped at 2 concurrent connections per the OSM tile policy; failed fetches negatively cached (15 s retry window) instead of re-requested every frame; at most one redraw per in-flight tile; inflight dedup via `Lazy` (no double downloads/leaked images); true LRU memory cache; disk cache keyed by tile-server template (switching providers can't serve stale styles — note: tiles cached under the old layout are orphaned until swept) and bounded at 256 MB with oldest-first pruning; `Dispose` on the shared `Default` singleton is a safe no-op; cache-dir failure degrades to memory-only.

### Fixed — Input robustness

- **A view exception in an input handler no longer crashes the app.** Pointer, key, text-input, and scroll handlers run synchronously inside the native Wayland/X11 event callback; an exception thrown by view code unwound through the native dispatch frame and aborted the whole process (SIGABRT). All input subscriptions now route through a `Guarded` wrapper that logs the exception instead. (Same protection applied to the opt-in GTK-surface input path.)
- **Maps: scrolling to minimum zoom no longer crashes.** On a tall HiDPI viewport at zoom 0 the world is smaller than the window, so the `VisibleRegion` write-back could build a `MapSpan` from an out-of-range longitude (the map pans horizontally without bound) — MAUI's `Location` constructor rejects longitudes outside [-180, 180] and threw. `LinuxMapHandler.PushVisibleRegion` now normalizes longitude into range, clamps latitude and the span degrees, and bails on any non-finite value.

### Changed — Tray icons

- **Hide/Show now toggles the indicator's status instead of destroying and recreating it.** `TrayIcon.Hide` sets the StatusNotifierItem to `Passive` (GNOME's AppIndicator host hides it entirely; KDE Plasma moves it to the hidden/expander area) and keeps the object alive so `Show` re-activates it instantly; real teardown happens on `Dispose`. Destroying per-hide was worse: libappindicator + KDE Plasma only drop a tray item when the owning **process exits**, so a destroyed indicator left a dead, still-cached entry in Plasma's overflow and blocked a clean re-show. Note for KDE users: getting a hidden icon out of the overflow/expander entirely is a Plasma tray-configuration choice (right-click tray → Configure → set the entry to "Shown"/"Hidden"), not something an SNI app controls at runtime. The XEmbed fallback backend (non-SNI desktops) still removes the icon fully on Hide.

### Fixed — Tray icons

- `app_indicator_set_icon_full` and `app_indicator_set_label` were bound with a missing third parameter, passing a garbage pointer on every icon/tooltip update (undefined behavior on all desktops). Correct 3-arg signatures now.
- Menu-item callback lifetime is now GTK-owned via `GClosureNotify` — the old code freed delegate `GCHandle`s on menu rebuild while a popped-open old menu could still invoke them (use-after-free), and `Remove` leaked the indicator (now `g_object_unref`'d, also fixing duplicate StatusNotifierItem registrations on Hide/Show cycles).
- All GTK/appindicator calls marshal to the GLib main thread; `TrayIcon.Activated` docs now state plainly that the AppIndicator backend cannot raise it (SNI left-click opens the menu by design).

### Fixed — Printing

- The blocking CUPS submit no longer runs on the UI thread; new `EnumeratePrintersAsync`/`PrintFileAsync` variants, and the sync APIs warn once when called on the main thread.
- `PrintSkiaPagesAsync` pages are committed only after `renderPage` confirms them (via `SKPicture` replay), so returning `false` on the first page prints nothing instead of a blank page; the temp PDF is created owner-only (0600).

### Fixed — MediaElement

- `MediaHardwareAccelerationService.Apply` guards on `gst_is_initialized()` (an empty pre-init registry previously produced misleading "install gstreamer1-vaapi" advice and silently did nothing).
- Original decoder ranks are snapshotted before modification and `Apply(Auto)` restores them — toggling `Prefer`/`Disable` at runtime is now fully reversible. Rank changes remain process-global (documented).
